# README Writer

按照「功能 → 部署使用 → 实现简述」三段结构撰写项目 README。实现部分保持简洁：让读者知道底层大概怎么实现即可，不展开细节长文。

## 写作流程

1. **先读代码再动笔**（保证描述准确，不臆测）：
   - 项目入口：启动方式、启动脚本、命令行入口；
   - 核心模块的主流程文件（读文件头部 docstring 即可了解职责，不必逐行读完）；
   - 配置文件/配置类：列出必配项、默认值、可调优项。
2. **用用户的消息语言撰写**，命令/路径/字段名保持原样。
3. 读完必要文件后**立即写**，不要长时间规划。

## 结构模板

### 一、项目功能

- 开头一段话概括：项目是什么、分几个模块/能力、技术栈一句话；
- 每个模块用「功能 | 说明」两列表格列出**用户可感知的功能点**，一行一个；
- 只写"能做什么"，不写"怎么做到"。

### 二、部署与使用

按可复制的操作步骤排序：

1. 环境要求（语言版本、外部依赖如数据库/扩展、是否需要 API Key）；
2. 安装依赖（命令）；
3. 配置（.env/配置文件代码块示例：必配项 + 常用可选项及默认值）；
4. 初始化（如有建库、导入数据等一次性步骤，注明幂等性与首次运行耗时）；
5. 启动（所有启动方式：双击脚本、命令行等）+ 访问地址；
6. 使用步骤（按页面操作顺序编号，每个功能 1-5 步）；
7. 常用 API / 命令一览表（如有）。

### 三、底层实现简述

每块 3-8 行，讲清思路即可：

- 核心数据流用一行箭头链表示：`输入 → 处理A → 处理B → 输出`；
- 有状态流转/分支逻辑时用一个紧凑 ASCII 小图（节点名 + 分支条件）；
- 每个要点回答：数据从哪来、怎么处理、存到哪、怎么取；
- **不写**：逐文件讲解、函数签名、参数表、设计权衡长文。

## 风格要求

- **简洁**：能一句说完不用两句，表格优于长段落；
- **具体**：命令、路径、默认值写真实值，不写"参见文档"糊弄；
- **准确**：所有描述必须来自实际读到的代码，不确定就去读，读完再写。
